# Numazu Pilgrimage Guide / 沼津圣地巡礼导航

A lightweight web pilgrimage guide for Love Live! Sunshine!! / Aqours fans visiting Numazu.

This project focuses on a clean map-first experience: curated spots, practical pilgrimage notes, local check-in states, and hand-arranged route recommendations.

## Live Demo

Live Demo: https://numazu-pilgrimage-guide.vercel.app/

## Core Features

- Numazu pilgrimage spot map
- Spot detail panel with pilgrimage, access, photo, duration, and tag notes
- Area / type / character filters
- Keyword search across names, descriptions, labels, and tags
- Business-hours search across opening times, regular holidays, price notes, and remarks
- Google Maps navigation links
- Visited / wishlist / favorite states
- localStorage persistence
- Hand-curated recommended pilgrimage routes
- Route completion progress based on visited spots
- Ordered route spot sequence
- Google Maps links for each route spot

## Project Highlights

- Fan-oriented travel workflow for Love Live! Sunshine!! / Aqours pilgrimage planning.
- Spot data has been expanded to 30+ manually curated locations.
- The data focus is not raw quantity, but pilgrimage usefulness: route flow, transport context, photo timing, and fan-friendly travel pacing.
- Spots are organized into product layers: `pilgrimage_core`, `food`, `shopping`, `hotel`, `transport`, `scenic`, and `auxiliary`.
- The home map defaults to featured pilgrimage spots to avoid marker overload.
- Users can switch to all verified spots to inspect the full Google Maps import dataset.
- Food, lodging, shopping, scenic, and auxiliary spots are kept as route-planning references without polluting the default pilgrimage map.
- The map uses a map-first layout with collapsible filter and spot-list drawers.
- Spot details open as a closeable floating card on desktop and a bottom sheet on mobile.
- Map markers use self-made category icons for restaurants, cafes, shops, hotels, transport, information desks, parks, shrines, seaside spots, aquariums, onsen, museums, and anime-related places.
- Users can switch to a custom icon mode and choose icons per marker category.
- Marker mode and custom category icons are saved in localStorage and use only custom CSS / inline SVG, not official artwork, logos, or character images.
- Spot data is manually maintained by the author, not automatically scraped.
- Business-hour notes can be shown for matched spots, including weekday hours, weekend/holiday hours, regular holidays, price notes, and travel remarks.
- Recommended routes are manually arranged by the author, not generated by automatic path planning.
- Route design focuses on realistic fan pilgrimage pacing, spot order, transport choices, and photo-friendly travel flow.
- The MVP stays intentionally lightweight: no backend, no login, no cloud sync, and no external database.

## Data Notes

Spot data lives in `src/data/spots.ts` and is manually organized by the author. The current dataset includes 30+ practical pilgrimage and travel reference spots around Numazu Station, downtown Numazu, Numazu Port, Mito, Uchiura, Nagaisaki, Awashima, and nearby seaside areas.

The dataset is designed as a fan travel aid, not an official guide. It uses conservative wording for places where official collaboration status should not be assumed.

## Data Accuracy / Coordinate Verification

Spot data is manually curated by the author. Map coordinates are not guessed by the model.

Google Maps search URLs are only used as manual verification entry points. A spot is marked as `verified` only when its coordinate has been parsed from a real Google Maps place URL containing `@lat,lng` or `!3dlat!4dlng`, or when it has been manually confirmed in Google Maps.

Unverified spots are marked as `needs_review` and are not shown as map markers by default. They still appear in the spot list and detail panel so they can be reviewed manually.

Users can also provide a batch of Google Maps place URLs for coordinate verification. The project parses `!3dlat!4dlng` first, then falls back to `@lat,lng` when needed.

Links that clearly match existing spots update those spots to `verified`. Links that do not match existing spots are added as new verified spots and listed in `docs/verified-coordinate-import-report.md`.

All imported coordinates come from user-provided Google Maps place URLs. They are not guessed from place names or generated by the model.

The current formal spot dataset only keeps places that have a user-provided Google Maps place URL. Older unverified legacy spots have been removed from `src/data/spots.ts`.

Future spots should first be supplied as Google Maps place URLs, then imported as verified coordinates. This keeps every map marker tied to a checked place URL and avoids model-guessed coordinates.

The formal spot list is synchronized from `docs/reference/location.md`. Updating that file with new full Google Maps place URLs is the supported way to add locations. URLs removed from `location.md` are removed from the formal `spots.ts` dataset.

Spot names are localized for the Chinese UI. The main display name prioritizes a natural Chinese name, while Japanese names and the original Google Maps place name are preserved where possible for manual cross-checking.

Name localization does not change coordinate provenance: coordinates still come from user-provided Google Maps place URLs.

Business-hour data is maintained separately from coordinate data. The current reference sources are `docs/reference/numazu.html` and `docs/reference/沼津店舗.pdf`; they are used only for opening hours, regular holidays, weekend/holiday hours, price notes, and remarks. They are not coordinate sources and do not add spots unless the place also appears in `location.md`.

Business hours may change. Before traveling, check Google Maps or the shop / facility official information.

The spot detail panel now prioritizes practical information: Google Maps navigation, local check-in buttons, business hours, and personal notes. Template-like pilgrimage, access, and photo tips are kept in data for future curation but are no longer emphasized in the main UI.

Personal spot notes are stored locally with keys like `numazu-spot-note:<spotId>`. They are never uploaded or synced.

This workflow is intentional: a pilgrimage map is only useful if it avoids sending fans to inaccurate locations.
